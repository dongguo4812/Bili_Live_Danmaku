# 歌曲模块（整合版）

歌曲业务逻辑从原独立点歌项目迁移，保留：
- QQ → 酷狗 → 网易云 → 酷我搜索顺序，每个平台最多 20 条（由配置控制）。
- 全平台优先精确歌名和精确歌手；只有不存在精确歌手结果时，才使用歌手包含匹配。
- Live/DJ/Cover/翻唱/伴奏/纯音乐等版本过滤。
- 入队时保存每个平台的完整匹配信息和歌曲 ID；播放及回退时不重新搜索。
- 洛雪播放调用、5 秒播放状态核验；当前音源未能确认播放时才尝试下一个已保存音源。
- 管理员切歌可以中断核验和音源回退，不会被后续核验补发暂停。
- 当前歌曲、队列查重、冷却、粉丝牌校验、管理员切歌、点歌开关和展示通知。

整合边界：
- 不创建自己的 B 站二维码登录、Cookie 文件或 LiveDanmaku 连接。
- 不创建独立 HTTP 服务或强制重设根日志。
- 通过统一事件总线接收 `danmaku` 标准事件。
- 歌曲模块启动默认关闭；生命周期由统一 ModuleManager 控制。
- 暂停保留当前曲目进度和队列；空队列暂停/恢复不会控制用户在洛雪中播放的其他歌曲。
- 关闭时停止机器人当前点播（洛雪官方 API 没有独立停止接口，因此以暂停当前曲目结束流程）、清空机器人队列。
- 断线暂停与重连恢复只作用于歌曲模块自身；恢复时刷新主程序统一 Cookie。

控制接口：
- `POST /api/modules/music/start|pause|resume|close`
- `GET /api/music/queue`
- `POST /api/music/action`（skip/delete/clear/set_song_request）

配置与管理员：
- 普通设置：`config/local/music.json`。
- 管理员 UID：统一在系统设置页 `/settings` 配置，保存在 `config/local/app.json`，歌曲和视频模块共用。
- 每次主程序进程启动时点歌请求开关默认开启；关闭请求开关只阻止普通观众新增请求，不清空已有队列，也不影响管理员切歌。
