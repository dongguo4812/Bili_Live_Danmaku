## 功能概览

### B站连接

- 使用 B 站 WEB 二维码登录，不支持匿名连接。
- 登录成功后保存 Cookie；启动时和连接前都会检查登录凭据。已有有效凭据和房间号时，启动会自动连接已保存的直播间。
- 登录凭据失效时可重新扫码。
- 扫码登录完成后可继续连接直播间，无需再次扫码。
- 通过 LiveDanmaku WebSocket 接收直播间事件。
- 支持意外断线后自动重连；可在配置文件中调整重连行为和间隔。
- 管理页面只有在收到 B 站 WebSocket 验证成功事件后才显示连接成功。

### Live2D 与弹幕

- 支持 Live2D Cubism 2（MOC2）与 Cubism 5 R5（MOC3）两套独立运行时，模型目录、模型选择和配置相互隔离。
- MOC2 默认模型 ID 配置为 `live_uu`；MOC3 使用独立模型目录和独立模型选择。
- 支持普通弹幕、礼物和醒目留言（SC）的展示。
- 弹幕以对话框形式显示，可调整位置、尺寸、字体、同时显示条数和显示时长。
- 页面背景保持透明，适合叠加到 OBS 场景中。
- 根据实际播放音频驱动嘴型；两套运行时分别检测模型可用参数，不支持的模型会明确提示。

### Edge TTS

- 普通弹幕、礼物、SC 分别提供独立播报开关。
- 可配置中文语音音色、语速、音量和最大等待队列长度。
- 可设置礼物最低金额门槛。
- 礼物和 SC 使用高优先级，普通弹幕使用低优先级。
- 当前正在播放的语音不会被新消息打断。
- 等待队列已满时，优先丢弃队列中最早的一条普通弹幕语音；若没有可丢弃的普通弹幕，则新语音不入队。
- 提供测试语音功能。

SC 播报示例：

- 有金额：`东郭老贼来了发来价值五十元的醒目留言：主播什么时候下播？`
- 无金额：`醒目留言，东郭老贼来了说：主播什么时候下播？`

## 运行环境

- Windows 10/11
- Python 3.10 或更高版本
- 可正常访问 B 站登录与直播 API 的网络环境
- OBS Studio（需要 OBS 综合展示源自动刷新时）
- OBS WebSocket 服务器（OBS Studio 内置，默认端口为 `4455`）

项目依赖见 [requirements.txt](requirements.txt)，其中包含 Flask、requests、bilibili-api-python、websocket-client、qrcode 和 edge-tts 等。

## 安装与启动

### 运行环境

需要 Python 3.10 或更高版本。请确保命令行中的 `python` 指向你准备使用的系统 Python。

### 启动程序

1. 下载或克隆本仓库。
2. 在项目根目录打开 PowerShell，使用同一个 Python 安装依赖：`python -m pip install -r requirements.txt`。
3. 双击项目目录中的 `start.bat`。脚本直接使用 `python` 启动，不会创建或激活虚拟环境，也不会自动安装或升级依赖。
4. 打开管理页面：

   `http://127.0.0.1:8768/`

5. OBS Live2D 透明展示页面：

   `http://127.0.0.1:8768/live2d/display`

使用期间请保持启动程序的控制台窗口运行。正常停止时，可在控制台按 `Ctrl+C`；也可以使用窗口关闭按钮退出。程序退出时不会修改 OBS 来源的显示/隐藏状态。如果依赖缺失，启动脚本会提示需要手动执行的安装命令。

### 手动启动

在项目根目录打开 PowerShell：

```powershell
python -m pip install -r requirements.txt
python main.py
```

源码启动和打包脚本统一使用 `python` 命令所指向的系统 Python。主项目以源码模式启动 LOL Hex 时，扩展会直接复用主程序的 `sys.executable`，不会再读取 `LOL_HEX_PYTHON` 环境变量。已有的 `.venv` 文件夹不会被自动删除，但这些启动和打包脚本不再使用它。

## B站登录与直播间连接

1. 在管理页面填写直播间房间号并保存，房间号保存在 `config/local/live.json`。
2. 点击“扫码登录”，使用 B 站手机客户端扫描二维码并确认登录。
3. 登录成功后，程序从 B 站二维码登录流程取得 Cookie，并安全保存到 `credentials/bilibili.json`。
4. 如果本机已经保存有效登录凭据和有效直播间号，程序启动时会自动尝试连接该直播间；无需每次手动点击“连接直播间”。
5. 刚完成扫码登录且已经保存直播间号时，程序也会自动发起连接。
6. 只有收到 B 站 WebSocket 验证成功事件后，页面才会显示“已连接”。连接异常时会按配置自动重连。
7. 需要手动停止时点击“断开连接”；重新连接仍需使用有效登录凭据。

二维码登录使用 B 站 WEB QR 登录接口。程序会跟进成功扫码后返回的跨域 ticket URL，以接收响应头中的登录 Cookie；不会仅凭二维码扫描成功就判定登录成功，而是继续验证已登录状态。

## Live2D 模型

项目同时支持两套相互独立的 Live2D 运行时：

| 版本 | 模型目录 | 模型配置入口 | 运行时 |
|---|---|---|---|
| MOC2 | `models/moc2/<模型ID>/` | `model.json` 或 `<模型目录名>.model.json` | `static/js/live2d.min.js` |
| MOC3 | `models/moc3/<模型ID>/` | `<模型目录名>.model3.json` | `static/js/live2d/moc3/` 中的 Cubism 5 R5 Core / Framework |

完整展示页 `/live2d/display` 根据 `config/local/live2d.json` 中的 `runtime_version` 加载对应运行时。MOC2 与 MOC3 使用独立模型目录，并分别保存模型选择和模型偏好；切换版本不会把另一版本的模型设置覆盖掉。默认 MOC2 模型 ID 配置为 `live_uu`；若本机没有该模型资源，请在展示页选择已安装的模型，或将合法授权的模型放入对应目录。MOC3 未配置默认模型时会从可用模型中自动选择。

模型能力面板会检查模型主体、贴图、动作、表情、物理配置、HitArea 触摸区域映射和 TTS 嘴型参数。MOC3 动作、表情、触摸动作映射和快捷键均由 Cubism 5 运行时执行；功能是否可用仍取决于模型资源本身是否声明相应内容。

TTS 嘴型同步依赖模型本身提供可用的嘴型参数。支持 LipSync 参数组或兼容嘴型参数的模型可以同步；如果模型没有声明有效的 LipSync 参数且没有兼容参数，界面会提示不支持。这属于模型资源能力限制，不代表运行时加载失败。

模型资源需要具有合法使用授权。新增模型时，请将资源放入对应版本目录，并确认模型配置引用的纹理、动作、表情、物理等文件路径正确。

### OBS 浏览器源地址

在 OBS 中添加“浏览器”来源，URL 填写：

```text
http://127.0.0.1:8768/live2d/display
```

建议浏览器源分辨率与 OBS 实际输出画布一致，例如 1920×1080，避免低分辨率拉伸造成模糊。

该地址用于独立 Live2D 展示。使用综合展示时可添加 `/display/combined` 或指定布局地址；全局语音引擎由程序通过 OBS WebSocket 自动创建，无需手动添加 `/voice/display`。

## 弹幕设置

管理页 `/danmaku` 用于配置空闲随机提示，并查看 B 站登录与直播间连接状态。空闲提示只会在真实连接成功且没有新消息时出现；收到真实弹幕、礼物或醒目留言后会立即清除。它是纯文字提示，不触发 Live2D 动作，也不会进入语音播报队列。设置保存在 `config/local/danmaku.json`。旧版本保存在 `live2d.json` 的空闲提示会在首次启动时自动迁移，原有设置不会丢失。

## 弹幕对话框

在展示页面左上角点击“设置”，可调整：

- 模型：选择已安装的 Live2D 模型。
- 模型大小、水平位置和垂直位置。
- 弹幕对话框水平位置、底部位置、宽度和最大高度。
- 弹幕字体大小。
- 同时显示的弹幕条数。
- 每条弹幕的显示时长。

滑块调整会即时预览；点击设置面板底部的“保存设置”后才会保存。每个 Live2D 模型分别保存自己的模型变换和弹幕对话框设置。

## 语音播报（Edge TTS）

在语音播报管理页 `/voice` 配置 Edge TTS：

- 普通弹幕、礼物、醒目留言（SC）开关。
- 语音音色。
- 语速和音量。
- 最大等待队列长度。
- 礼物最低金额。

语音由 Edge TTS 在线合成，合成后的 MP3 文件暂存在系统临时目录 `bili_live_danmaku_tts`。程序在后续合成请求时清理超过一小时的旧文件。

语音队列只由一个独立的 OBS 全局语音引擎页面消费，不再由每个综合展示页面分别播放。程序连接 OBS WebSocket 后，会自动创建或复用一个隐藏的 2×2 浏览器源“B站直播弹幕助手-全局语音引擎”，并将同一个 OBS 输入加入当前场景集合的所有场景。切换场景时，这个共享浏览器源保持运行，因此当前语音不会因旧场景页面切换或销毁而中断；同一条弹幕也只会进入一次语音队列。Live2D 页面从统一播放状态同步音量，只让当前可见场景中的模型呈现嘴型变化。请不要删除或禁用这个自动创建的全局语音引擎来源。语音管理页的“加入 OBS 语音试听队列”也会通过同一引擎播放。

## OBS 配置与综合展示刷新

程序通过 OBS WebSocket v5 管理综合展示刷新和全局语音引擎：

- 程序启动后开始检查 OBS WebSocket；OBS 尚未启动或暂时不可用时，每 3 秒重试连接。
- OBS WebSocket 连接成功后，刷新指向当前服务地址下 `/display/combined` 或 `/display/combined/<布局ID>` 的综合展示浏览器源，并确保全局语音引擎已创建。
- 全局语音引擎是一个共享的浏览器输入，程序会将它加入当前场景集合的所有场景；它使用 2×2 透明页面，并关闭“场景非活动时关闭源”和“场景激活时刷新”行为。切换场景时仍是同一个浏览器输入，不会启动第二份播放器。
- 在综合展示布局编辑页点击“保存当前布局”后，程序会在后台尝试连接 OBS WebSocket；连接可用时刷新综合展示浏览器源，并检查全局语音引擎是否仍在所有场景中。此操作不阻塞布局保存。
- 启动检查成功后停止周期性检查；整个过程不依赖 B 站直播间连接状态。
- 程序不会改变综合展示来源的显示/隐藏状态；仅创建或启用专用的全局语音引擎场景项。请勿删除或禁用该来源。
- 程序退出时不会删除全局语音引擎来源。

OBS WebSocket 普通配置保存在 `config/local/obs.json`，包含地址、端口、超时和来源名称。密码统一在凭据管理页录入，保存在 `credentials/obs.json`；Windows 使用当前 Windows 用户上下文的 DPAPI 加密，页面不会回显密码原文。非 Windows 开发环境使用仅本机文件权限保护的存储格式，不应将该环境的凭据文件复制到其他设备；正式 Windows 使用时应由目标 Windows 用户重新保存凭据。

系统设置页面：`http://127.0.0.1:8768/settings`；统一凭据入口：`http://127.0.0.1:8768/credentials`。请在 OBS 的“工具 → WebSocket 服务器设置”中启用 WebSocket 服务器，并确认地址、端口和来源名称正确。

## 本地数据与安全

项目将数据分为三类：

- `config/`：普通功能配置，例如直播间号、模型设置、语音设置、歌曲/视频参数和 OBS 地址端口。
- `credentials/`：敏感凭据，例如 B 站 Cookie、OBS 密码和第三方 API Key。Windows 下使用 DPAPI 保护。
- `data/`：运行数据，例如歌曲/视频队列缓存、Chrome Profile 和综合展示布局。
- `logs/`：运行日志，不得包含 Cookie、密码或 Token。

当前版本不再读取或迁移旧版 `user_settings.json`、根目录 `config.json`、`room_config.txt`、`obs_config.txt` 或独立管理员 UID 文本文件。当前本机配置统一位于 `config/local/`；直播间号位于 `config/local/live.json`，Live2D 模型和按模型保存的弹幕框布局偏好位于 `config/local/live2d.json`，弹幕空闲提示位于 `config/local/danmaku.json`，语音播报偏好位于 `config/local/voice.json`，OBS 普通设置位于 `config/local/obs.json`。系统管理员 UID 只保存在 `config/local/app.json`。OBS 密码和 B 站 Cookie 分别保存在 `credentials/obs.json`、`credentials/bilibili.json`，不要把 `credentials/` 上传到 GitHub。

## 统一模块与综合展示

管理入口：`http://127.0.0.1:8768/`。接入中心在“B站登录与直播间连接”下方提供统一的“功能启停控制”面板：

- 歌曲点播、视频点播、语音播报各自提供“启动/关闭”与“暂停/恢复”两个双向切换按钮；Live2D 使用“启用/停用”切换按钮。
- 面板显示各模块实际运行状态，并使用统一颜色：绿色表示正常运行/已连接/已启用，黄色表示暂停，蓝色表示等待或状态切换中，灰色表示关闭/停用/未连接，红色表示异常。
- 模块详细页面保留队列、切歌、点歌开关、配置和试听等专属操作；生命周期控制统一放在接入中心。
- 歌曲和视频模块相互独立，启动、暂停、恢复和关闭不会影响对方。
- 每次主程序启动时，歌曲和视频模块默认关闭；语音模块在首次完成 B 站 WebSocket 认证连接后自动启动。Live2D 是否启用由其独立开关和配置决定，不依赖直播连接。
- 直播连接断开时，歌曲、视频和语音模块会暂停；重新认证连接后，只恢复断线前处于运行状态且没有被用户手动更改的模块。
- 歌曲模块保留 QQ、酷狗、网易云、酷我四平台搜索匹配、音源 ID 入队保存、5 秒播放核验失败回退、粉丝牌验证、管理员切歌和观众点歌开关。
- 视频模块保留 Chrome/Selenium 播放、BV 校验、队列、播放结束监控和 OBS 来源显隐；网页全屏只在确认视频进度后尝试 W；视频暂停/关闭不会控制洛雪。
- 歌曲设置页：`/music/settings`；视频设置页：`/video/settings`。修改模块配置前需要先关闭对应模块。
- 系统管理员 UID 在系统设置页 `/settings` 统一配置，歌曲和视频模块共用；不再分别维护 `data/music/uid.txt`、`data/video/uid.txt`。
- 独立展示页面：完整 Live2D/弹幕/TTS 展示 `/live2d/display`；MOC2 单独展示 `/live2d/moc2/display`；弹幕 `/danmaku/display`；语音 `/voice/display`；歌曲队列 `/music/display`；视频队列 `/video/display`；歌曲信息组件 `/music/widget`。
- Live2D 设置 API 使用 `/api/live2d/` 前缀；模块生命周期 API 使用统一模块路由。
- 综合展示布局编辑页：`/dashboard`。可添加/移除模块、拖动位置、调整大小，并手动保存；支持多套布局的创建、复制、重命名、删除和设为默认。
- OBS 默认综合展示地址：`/display/combined`；指定布局使用 `/display/combined/<布局ID>`，不同 OBS 场景可分别绑定不同布局。视频模块只显示当前播放、下一条、待播队列和通知，不嵌入视频画面。


### LOL Hex 扩展

LOL Hex 以独立进程方式运行，由接入中心的「功能启停控制」统一启动和停止；扩展负责英雄联盟客户端识别、F1 截图、本地 OCR、海克斯数据管理、海克斯展示和战绩条。

- Windows 下启动 Hex 会请求管理员权限。F1 全局截图依赖管理员权限，因此需要在 UAC 提示中允许启动；取消授权会导致启动失败。
- 主项目托管模式下，OBS WebSocket 连接、重连和浏览器源刷新由主项目统一负责；Hex 不另行建立 OBS WebSocket 连接。
- 接入中心可打开 Hex 管理页：`/extensions/lol-hex/`；海克斯展示页：`/extensions/lol-hex/display`；战绩条：`/extensions/lol-hex/bar`。独立运行 Hex 时，默认服务端口为 `8767`，页面分别为 `http://127.0.0.1:8767/`、`/display` 和 `/bar`。
- 管理页提供扩展运行状态、截图与数据管理、海克斯索引维护等操作。游戏中按 **F1** 冻结画面并框选截图区域；再次按 **F1** 或按 **Esc** 可取消框选。
- 截图与数据管理区域会显示当前截图目录，并提供清空卡片和截图的操作。海克斯索引支持检查并更新、重置；页面显示的索引条数以当前实际数据为准。
- 截图通过本地 OCR 和海克斯索引进行名称识别。无法可靠匹配名称时仍可保留截图供人工查看，不会凭空生成海克斯名称。
- 扩展会定期检查英雄联盟客户端及账号/对局状态；战绩截图采集、卡片处理和展示均由扩展内部负责。
- Hex 默认配置模板为 `config/default/lol_hex_display.json`，本机实际配置为 `config/local/lol_hex_display.json`。首次升级时，如果本机 JSON 尚不存在且旧版 `extensions/lol_hex_display/config.txt` 存在，程序会将可识别字段迁移到 JSON；JSON 已存在时不会被旧文件覆盖。
- 本机运行数据位于 `extensions/lol_hex_display/data/`、`screenshots/` 和 `logs/`；进程号记录在 `lol_hex_display.pid`。这些目录和 PID 文件由 `.gitignore` 排除，不作为源码提交。Python 运行时生成的 `__pycache__/` 同样会被忽略。
- 扩展单独打包脚本不会打包本机数据；主项目 `build.bat` 会在生成扩展后，将当前电脑上已经存在的 Hex `data/`、`screenshots/`、`logs/` 复制到文件夹版输出中。这是本机打包行为，与 GitHub 是否跟踪这些文件相互独立。
- 在综合展示编辑器中，`LOL 战绩条` 和 `LOL 海克斯展示` 是两个独立组件，可分别添加、移动、缩放和移除。
- 独立扩展说明见 [LOL Hex 扩展文档](extensions/lol_hex_display/README.md)。
- 歌曲和视频展示页的待播列表显示数量可分别在 `/music/settings` 与 `/video/settings` 配置，范围为 1～1000，默认各显示 10 条；页面同时显示完整待播总数，不会因展示条数限制而改变实际队列。

GitHub Actions 会在 Ubuntu 环境执行 Python 编译、配置与离线回归测试，并在 Windows 环境额外执行真实 DPAPI 加解密和配置退役测试。CI 通过不等于所有设备上的人工联调均已完成；歌曲和视频模块仍需结合洛雪音乐、Chrome、OBS WebSocket 和实际直播间环境进行本机验证。

## 常见问题

### 管理页面提示未登录

请重新点击“扫码登录”，使用 B 站手机客户端完成扫码确认。二维码扫描完成不等于登录验证完成；请等待页面显示登录成功。

### 登录成功，但直播间没有显示已连接

请确认房间号正确，并等待 WebSocket 完成认证。页面只有在收到验证成功事件后才会显示连接成功。可检查控制台日志和网络连接状态。

### Live2D 模型没有显示

确认所选版本的模型目录中存在对应入口配置及其引用的纹理等资源：MOC2 位于 `models/moc2/<模型ID>/`，MOC3 位于 `models/moc3/<模型ID>/`。再检查浏览器控制台是否有资源加载错误或 WebGL 错误。模型文件需要具有合法授权。

### OBS 综合展示页没有自动刷新

确认 OBS 正在运行、OBS WebSocket 服务器已启用、地址和端口正确、凭据管理页中已正确保存 OBS 密码，并确认综合展示浏览器源 URL 指向当前程序的 `/display/combined` 或 `/display/combined/<布局ID>` 页面。程序会在 OBS WebSocket 可用且找到该来源后刷新一次。

### OBS 没有语音

确认 Edge TTS 网络合成正常，TTS 开关已开启，礼物金额达到设置门槛，并检查 OBS 浏览器源的音频/自动播放策略。可使用“测试语音”按钮检查音频输出。嘴型同步依赖展示页实际播放的音频。

### 某些弹幕没有显示或播报

程序只能处理 B 站实际推送到直播间 WebSocket 的事件。如果弹幕未通过 B 站审核，或未出现在 B 站原生聊天列表中，机器人也无法接收到该弹幕。
